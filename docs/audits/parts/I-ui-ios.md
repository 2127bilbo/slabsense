# I. UI and iOS fit

**Summary.** The app is a single 480 px-wide dark column (`src/App.jsx:2438`) of inline-styled React with a sticky header, a top tab bar and 14 full-screen `position:fixed` overlays; nothing uses `env(safe-area-inset-*)`, 580 font sizes are fixed px (148 of them 7–9 px), and 11 ARIA attributes exist in the whole UI (9 in the centering tool).
Three Blockers are UI-visible: the pricing modal shows hard-coded Stripe prices, sends the WebView to Stripe Checkout / the Customer Portal via `window.location.href`, and the Terms/Privacy sentence on sign-up links to nothing. The "I Understand" gate is a sound estimate disclaimer but is the only onboarding and is stored in `localStorage`.
Counts: 3 Blocker, 11 Major, 12 Minor, 6 Note. Screens that MUST change for the migration: Pricing, Credit balance, Camera viewfinder, Auth modal, Collection detail (slab order + cert link), Settings (manage subscription / restore), Analyzing (error dead end).

## 2. Camera and capture: today, and after native capture

**Today.** `CaptureCardVertical` → `setCamTarget(side)` → `CameraViewfinder` (`App.jsx:906-1353`): `getUserMedia` 4096×3072 ideal; live outline from `liveCardQuad` (card model) with texture-grid fallback (`:959-1010`); lock after `LIVE_LOCK_FRAMES`; auto snap after `AUTO_SNAP_MS` (`:1037-1050`); bubble level from `deviceorientation` with the iOS permission button (`:1014-1028`); shutter → `captureFrame` JPEG 0.92 → `validateCap` (card model: not found / too small / too close / tilted) → Retake / Use Photo / Use Anyway → `onCapture(dataUrl)` → `handleCam` → `handleSetFrontImage` (`App.jsx:1897`) → `analyzePhotoQuality` → `PostCaptureCentering` with `suggestOuter` / `suggestInner` (`App.jsx:2501-2510`) → `CardIdentifier` (front only) → capture card shows Ready / Issues.

**What goes.** `CameraViewfinder` entirely (live detection loop, bubble level, orientation permission, drop-zone upload, HEIC desktop check, `markModelPass` around the live loop). The `AUTO_SNAP_KEY` / `LIVE_INTERVAL_MS` knobs go with it. "Warm the card model while framing" (`:910`) moves to app start or to the capture tap.

**What stays unchanged.** `CaptureCardVertical`, `handleSetFrontImage` / `handleSetBackImage`, `analyzePhotoQuality`, `PostCaptureCentering` (+ `Loupe`, `CornerHandles`), `suggestOuterCorners` / `suggestInnerCorners`, `CardIdentifier`, `run()`.

**What the native path must supply.** One call that resolves to a data URL (or `blob:`/file URL) of the full-resolution JPEG for `handleSetFrontImage(img)` / `handleSetBackImage(img)`, with EXIF orientation already applied (today `captureFrame` draws the video frame, so orientation never mattered; a native 48 MP photo arrives with EXIF). Then re-run `validateCap(src)` (`App.jsx:1355`; keep it as a pure function) and show a native-looking Retake / Use sheet, because the in-page post-capture preview lives inside the component that goes. Photo-library import must stay (the no-camera branch and the small upload button, `:1296`) as a second native picker. Decision D6 (48 MP) raises the data-URL size handed to `analyzePhotoQuality`, the centering crop and the Supabase upload; test on a 4 GB device with the model toggle on (STATUS "known phone problem").

## 4. Onboarding and the "I understand" gate

`App.jsx:2631-2644`. One modal, shown when `localStorage.slabsense_disclaimer_acknowledged` is unset: "SlabSense is an independent card analysis tool. We are NOT affiliated with any professional grading company (PSA, BGS, CGC, SGC, TAG, etc.). All grades shown are estimates only. Actual grades from professional services may vary significantly. Do not make financial decisions based solely on these estimates." Button: "I Understand". It reads as an estimate disclaimer plus a non-affiliation notice; it is not onboarding (no camera priming, no free-vs-paid explanation, no Terms/Privacy links). It is the only acknowledgement in the app; the footer repeats "Pre-grade estimate · DINGS-based · Not affiliated with TAG" at 8 px (`App.jsx:3484`) and names only TAG while the header lets the user pick PSA/BGS/CGC/SGC. Acceptance is per-device `localStorage`, which a WKWebView may clear under storage pressure, so it can re-appear; acceptable.

## 6. Styling architecture

Everything is inline `style={{}}`: there are 0 `.css` files in `src/`; the only CSS is the reset in `index.html:14-18` and six `<style>` tags for keyframes and range thumbs. Two "tokens" exist as module constants, duplicated per file: `mono="'JetBrains Mono','SF Mono',monospace"` and `sans="'Inter',-apple-system,sans-serif"` (`App.jsx:45`, `PricingPage.jsx:13`, `AuthModal.jsx:8`, `CollectionView.jsx:20`, `PostCaptureCentering.jsx:29`; `CreditBalance`/`PricingPage` drop `'SF Mono'`; `CollectionView.jsx:2014-2117` spells the strings out again). Colours are literal hex (`#0a0b0e` page, `#0d0f13` card, `#1a1c22` border, `#00ff88` success, `#6366f1`/`#8b5cf6` brand, `#ff9944` warn, `#f97316` deep) with no palette object. `fontFamily:mono` appears 460 times vs `sans` 67: nearly every label is uppercase, letter-spaced, 8–11 px monospace, which is the single biggest "not an iOS app" signal and the root of the Dynamic Type problem. Root is `maxWidth:480; margin:0 auto` (`App.jsx:2438`), so iPad and landscape render a narrow centred column on black. Hover handlers (`onMouseEnter`, `UserMenu.jsx:104`) and 70+ `cursor:` values are desktop leftovers. For Phase 3: one `theme.js` (colours, spacing, type ramp in `rem`, radii) imported everywhere; `mono` reserved for numbers (grades, ratios, percentages); `sans` (system `-apple-system`) for all labels and buttons.
