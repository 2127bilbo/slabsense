# J. Performance and stability

**Summary.** The on-device model pass is the one reproducible stability risk: a 12 MP pair plus the fp16 models puts ~450–600 MB of JS/WASM/bitmap memory in flight on a phone, the page reloads with no message, and the unsaved scan is gone; the crash guard fires only after that first reload and also fires falsely whenever the viewfinder is simply closed. Network has no size warning for ~205 MB of first-run model bytes (plus ~110 MB from huggingface.co for identification), no offline handling anywhere, and a paid grade killed at Vercel's `maxDuration` keeps the credit with no refund path. Build is lean (one 208 kB gz main chunk), API timeouts on the grade calls are right, and the double-submit guards hold.

Counts: **1 Blocker, 8 Major, 11 Minor, 6 Note** (J-01 … J-26).

## 1. Memory during a grade

Resident strings in `SlabSense()` state (`src/App.jsx`) for one card, 12 MP capture (4000×3000, JPEG q0.92 ≈ 4–6 MB → base64 ≈ 6–8 MB each; V8/JSC store these one byte per char):

| Held in state | Lines | Count | Size (12 MP) |
|---|---|---|---|
| `fI`, `bI` full-res photo dataURLs | 1510 | 2 | 12–16 MB |
| `frontCroppedImage`, `backCroppedImage` (crop at **full** photo width, `PostCaptureCentering.jsx:430` passes `imgSize.w`) | 1593–1594 | 2 | 10–14 MB |
| `fM`, `bM` vision maps: 4 **PNG** dataURLs each at 1400×1960 (`image-utils.js:178-181`) | 1512 | 8 | 25–40 MB |
| `fR.scaledImgUrl`, `bR.scaledImgUrl` 1400 px JPEG (`App.jsx:171`) | 1511 | 2 | ~1 MB |
| `enhancedCards.front/back` (3D view: same strings re-referenced, `App.jsx:2419-2421`) | 1545 | 0 extra | — |
| Camera `captured` (until the viewfinder unmounts) | 915, 1059 | 1 | 6–8 MB |
| `tcgdexImage` | 1582 | URL only | — |

So 14 dataURL strings, ~50–70 MB, stay resident at step 2 — plus the decoded bitmaps the browser keeps for every `<img src={dataURL}>` on the Grade/Centering tabs (a full-res crop decodes to 4000×2800×4 ≈ 45 MB each).

Every place a full-resolution image is duplicated on the grade path (file:line):

- `App.jsx:1055-1058` capture: canvas at `videoWidth×videoHeight` (48 MB bitmap) → `toDataURL` (+6–8 MB string).
- `App.jsx:1125-1137` upload path: `readAsDataURL` (string 1) → `Image` decode (48 MB) → canvas copy (48 MB) → `toDataURL` q0.95 (string 2). Two base64 copies and two bitmaps of the same photo.
- `App.jsx:1358` `validateCap`: full decode again (48 MB) for the card model; `img.src` never cleared.
- `App.jsx:53` `analyzePhotoQuality` → `loadImg(src, 800)`: full decode + 800 px canvas + `getImageData`.
- `PostCaptureCentering.jsx:129` full decode for the 1400 px display; `centering-utils.js:105-130` full decode + full-res crop canvas (≈45 MB) → JPEG dataURL (string 3).
- `cardModels.js:109, 127` `suggestOuterCorners`/`suggestInnerCorners`: full decode of photo, then of crop (released via `img.src=''`).
- `App.jsx:169-171` `analyzeCardFull`: `loadImg(src)` 1400 px canvas + `getImageData` (11 MB) + `toDataURL` (`scaledImgUrl`).
- `App.jsx:189` `withModelDings`: `loadImageElement` full decode of the crop (45 MB) for 16 tiles; released after.
- `image-utils.js:105-181` `genMaps` ×2: 1400 px decode + 4 canvases (11 MB each) + 4 PNG `toDataURL`.
- `App.jsx:2225-2228` `cardKeyFor`: `${front}|${back}` concatenation (+14 MB string) → `TextEncoder` (+14 MB `Uint8Array`), on every `fI/bI` change and again in `startGradeJob`.
- `image-utils.js:81-86` `resizeImage` (used for every AI upload, `api.js:218, 351`): `loadImg` runs `getImageData` on the 2000 px copy (12 MB) it never reads; Deep does four in parallel (`api.js:1030-1034`).
- `scans.js:22` `fetch(dataUrl).blob()` ×3 on save, full-res, sequential.

Model memory (`cornerEdgeModels.js`, `corner-edge-runner.js`, `card-model-runner.js`): sizes from `training/weights/onnx/*.json` — card-v1 fp16 6.3 MB; corners-v3-phone-safe, edges-v2-phone-safe, centering_rgb-v2b fp16 56.6 MB each (two 45 MB parts, `scripts/models/upload.mjs:34`). Runtime: `ort.min.mjs` 368 kB + `ort-wasm-simd-threaded.jsep.wasm` 28.3 MB (WebGPU) or `.wasm` 14.2 MB. Loading one 54 MB model peaks at ~160 MB transient: two part `Uint8Array`s (`cornerEdgeModels.js:160`) + the joined copy (`:164-167`) + the runtime's own copy inside `InferenceSession.create`; the JS copies are dropped after (`corner-edge-runner.js:55-58` comment). Sessions are never released: after one grade with the centering tool, four sessions (~175 MB of weights, fp32-upcast on WASM → up to ~350 MB) stay alive for the page lifetime, and a NaN on WebGPU creates a **second** WASM session of the same model (`corner-edge-runner.js:84-87`). Cache API: `slabsense-models-v1` holds ~205 MB after the first full run, `slabsense-card-db-v1` ~20 MB; nothing evicts or reports usage.

**Peak heap estimate, 12 MP pair, first grade on a phone:** ~60 MB strings + 45 MB decoded crop for the model pass + 22 MB 1400 px canvases/ImageData + 160 MB model-load transient + 28 MB wasm module + 60–110 MB resident sessions + GPU/WASM arenas ≈ **450–600 MB** before the browser's own decoded-image cache for the `<img>` tags. iOS WKWebView content processes are commonly terminated in the 1–1.4 GB range on recent phones and far lower on 3–4 GB devices under camera load, which matches the reloads reported in `docs/STATUS.md`.

## 2. Crash guard and reload paths

- Guard: `cornerEdgeModels.js:69-92` brackets a pass with `localStorage` timestamp; `main.jsx:7` checks it before render and sets the toggle to off. User experience after an OOM reload: the page comes back on the Home tab, **no banner** (`modelPassCrashed` is imported at `App.jsx:29` and never used; the only message is in Settings, `src/components/Settings/*.jsx:295-299`). Lost: both photos, crops, centering data, software grade, and any AI job not yet applied (`fI/bI` live only in React state; nothing is persisted before the pass). A paid job that already started is recoverable through `readJobs()` polling on next sign-in (`App.jsx:1830+`), the free scan is not.
- Coverage: `withModelDings` (`App.jsx:195-200`), `suggestInnerCorners` (`cardModels.js:128-132`), `detectCardInSource` with `mark` (`cardModels.js:75-83`) and the **whole live viewfinder session** (`App.jsx:976, 1010`). The viewfinder mark is the gap in the other direction: the key is set the moment the camera opens and cleared only on effect cleanup, so closing the tab, backgrounding Safari until it discards the page, or a crash anywhere else while the camera is open leaves it set; the next launch within 10 min reads as a model crash and silently turns the models off. Nothing covers a reload during `genMaps`, `cropToOuterBounds` or the AI upload resizes, which are the same bitmaps.
- Not covered by design but should be: a Capacitor/WKWebView OOM kills the content process without reloading — the native shell will show a blank web view unless it listens for `webViewWebContentProcessDidTerminate` and reloads.

## 3. Startup

`npx vite build` (2026-10-01): `index-BpROA30R.js` **718 kB / 207.5 kB gz** (React, supabase-js, App, all components, model glue — the only script in `dist/index.html`); `transformers-DH2twgIt.js` 828 kB / 201 kB gz (lazy, `clip-matcher.js:93`, identification only; bundles its own nested onnxruntime-web, build warns on `eval`); `html2canvas` 202 kB (lazy, export); `index-qEfrVXE3.js` 15.8 kB and `id-rerank` 3.9 kB (lazy). Before first paint: `index.html` 1.3 kB with inline body CSS, then the 718 kB module; no `modulepreload`, no `preconnect` to Supabase or Google Fonts. Fonts: JetBrains Mono (6 weights) + Inter (4 weights) are injected as a `<link>` **inside the React tree** (`App.jsx:3485`), so they start downloading after the bundle executes and the UI re-flows on swap. Card DB shards are **not** loaded at startup — only on identification (`identify-card.js:52` → `clip-matcher.js` → `card-db-client.js:58`), sequentially per shard, into a 19,578×512 Float32Array (40 MB resident) from 20 MB of f16. The card model (6.3 MB + 28 MB runtime) starts loading when the viewfinder opens (`App.jsx:910`), ~2 s on Wi-Fi.

## 4. Network

- First-run bytes, no warning, no Wi-Fi gate anywhere (grep: no `navigator.connection`, no `onLine`, no size prompt): viewfinder 34.6 MB (runtime 28.3 + card 6.3); first software grade +113 MB (corners + edges); first centering suggestion +56.6 MB; total **~205 MB** on cellular before the first grade. Identification adds ~88 MB (`Xenova/clip-vit-base-patch32` quantized, fetched from **huggingface.co** — `clip-matcher.js:93-115` never sets `env.remoteHost`) + 20 MB card DB. A `Downloading…` progress exists only for CLIP; the model downloads show the generic `Checking corners and edges` line.
- Manifest: `models.json` is refetched `cache: 'no-store'` on every page load (`cornerEdgeModels.js:127`) with cached fallback — correct. Shards/parts: one retry after checksum mismatch, otherwise no retry anywhere.
- Timeouts/abort present: `postGrade` 150 s / 320 s (`api.js:178-195`), `analyzeCardWithVision` 60 s (`api.js:47`). **Without timeout or abort:** `cornerEdgeModels.js:107, 127` (model parts, manifest); `card-db-client.js:46, 60`; `App.jsx:2387` (restore job photos); `credits.js:24, 40, 61, 97, 122`; `slabs.js:19`; `tcgdex.js:48, 88, 254`; `trainingCapture.js:52`; every `supabase.storage.upload` (`api.js:227, 360`; `scans.js:30`) and every `supabase.from()` query; server side `api/_providers/anthropic.js:61,111` (`new Anthropic({apiKey})` with SDK defaults: 10 min timeout, 2 retries), `google.js:170`, `index.js:252`, `replicate-utils.js:28`.
- Offline per screen (no `onLine` check in the tree): Home — stats query fails to console (`App.jsx:1614-1641`), zeros shown, no message. Scan — capture and software grade work; models fail → `console.warn`, grade silently uses detectors (`App.jsx:208`), centering tool says "model could not place the frame". Grade tab AI/Deep — upload throws `TypeError`, caught as "network drop" and enters `pollJob` for **10 minutes** showing "Still working — waiting for the result…" with no job ever created (`App.jsx:2353-2356`). Save — `uploadCardImage` returns null, row insert throws → `savingStatus 'error'` for 3 s, no text. Cards (collection) — `catch` sets an error state. Identify — "Search failed. Check your connection." (`CardIdentifier.jsx:157`) for manual search; auto-identify logs only. Billing/Stripe — `credits.js` throws, surfaces as a generic error. Nothing throws uncaught; the problem is silence, not crashes.

## 5. API latency

- AI grade: 2 parallel 2000 px uploads (`api.js:293-295`) → one `anthropic.messages.create`, `max_tokens 3000` (`ai-analyze-unified.js:141`) → deduction regressor locally. Typical 20–60 s; `maxDuration: 120` (`:37`); client aborts at 150 s.
- Deep grade: 4 parallel uploads (`api.js:1030`) → references query → Pass 1 Claude → Pass 2 Claude, sequential in `DEFAULT_CONFIG.mode = SINGLE` (`deep-analyze-v2.js:45-50, 231, 299`); parallel/synthesize modes exist but are off. Typical 60–180 s; `maxDuration: 300` (`:40`); client aborts at 320 s. `maxDuration` 300 needs a Pro plan; on Hobby, Vercel caps at 60 s (fluid) and the deep path would be killed routinely — verify the plan.
- Refund path: `runGradeJob` (`api/_lib/gradeJobs.js:76-104`) refunds on any thrown or non-200 result. A Vercel kill at `maxDuration` is not an exception: the row stays `running`, the credit stays spent, no sweep exists (no `stale`/`expired` logic in `gradeJobs.js`), and the client's `pollJob` gives up after 10 min with `setStatus(null)` and no message (`App.jsx:2296-2320`). Provider calls have no timeout below `maxDuration`, so this is reachable on every slow Anthropic response.

## 6. Battery

- Viewfinder loop: `setTimeout` chain, 120 ms WebGPU / 300 ms WASM / 350 ms grid (`App.jsx:890, 978-1010`), skipped while hidden; cleared on cleanup. A frame costs a 320 px grid pass or a card-model pass on the full video frame, continuously while framing.
- Orientation: `useEffect` listener removed on unmount (`App.jsx:1013-1021`); but `requestOrient` (iOS 13+ path, `App.jsx:1026`) adds an **anonymous** `deviceorientation` listener that is never removed and keeps calling `setTilt` on an unmounted component. `gyro-input.js:127-139` adds `mousemove`, `touchmove` and (Android) `deviceorientation` for the app's lifetime for the Holo logo sparkle; on iOS it calls `DeviceOrientationEvent.requestPermission()` on the first touch anywhere (`:100-105`).
- Timers: `setInterval` in CardViewer3D spin (`CardViewer3D.jsx:330`) is not cleared on unmount; auto-snap interval is cleared (`App.jsx:1045-1050`); `pollJob` loop (`App.jsx:2300`) has no unmount/card-change cancel. All `setTimeout(() => setX(null))` status timers (`App.jsx:2098-2199`, `CollectionView.jsx:305-388`) run after unmount (harmless warnings).
- Video stream: stopped on accept (`App.jsx:1065`), close (`:1076`) and effect cleanup (`:965`); `retake` re-attaches the same stream. All exit paths covered.

## 7. Stale closures and races on slow devices

- `run` button is hidden during step 1 (`App.jsx:2717, 2738`); AI/Deep buttons disabled while in flight (`:2961, 2971`; `CollectionView.jsx:1121, 1157`); saves are serialized by `saveChainRef` (`:2068-2092`). Pass.
- "Start a new scan" at `App.jsx:2751` resets `fI/bI` and `resetGradingState()` but **not** `frontCroppedImage/backCroppedImage/frontCenteringData/backCenteringData/frontQuality/backQuality/tcgdexImage` (only `reset()` at `:1894` does). If the user cancels the centering tool on the next card, `run` grades the previous card's crop (`:1775-1776`) with the previous centering override.
- `validateCap` has no token: a retake while validation is pending lets the old result land on the new capture (`App.jsx:1060, 1141`).
- `pollJob` after a `TypeError` (`App.jsx:2353`) assumes a job row exists; offline it never does.
- ONNX concurrency: `card-model-runner.js:60-63` serializes runs; `corner-edge-runner.js` has no guard, and the exported `applyModelDings` runs front and back with `Promise.all` (`cornerEdgeModels.js:293-296`) — unused today (App runs sides sequentially), but the first caller gets "Session already started".
- `corner-edge-runner.js:63-79` caches a **rejected** `sessions[task]` promise forever (card-model-runner `:50` deletes on failure); one failed load (network blip, quota, a caught OOM) makes every later grade on that page silently fall back to detectors.

Log-only (user never sees it): `cardModels.js:85, 114, 134`; `cornerEdgeModels.js:304`; `App.jsx:208, 1004`; `scans.js:34` (returns null, scan saved without images); `identify-card.js:96`.
